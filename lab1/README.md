# Лабораторная работа 1 — вариант 4

Полный отчёт с выполнением задания, расчётами, графиками и таблицей соответствия требованиям находится в [Jupyter Notebook](lab1_big_data_scenario.ipynb). Вариант 4 — IoT Sensor Data. Выбранный бизнес-сценарий №4 из задания — анализ логов и мониторинг с целевым снижением MTTR на 40%.

## Источник и ограничения данных

Использован указанный для варианта датасет Kaggle: [IoT Dataset for Intrusion Detection Systems (IDS)](https://www.kaggle.com/datasets/azalhowaide/iot-dataset-for-intrusion-detection-systems-ids), файл `BoTNeTIoT-L01-v2.csv`. Файл данных и распакованный архив **не хранятся в Git**. Текущий источник содержит числовые сетевые признаки и категориальные `Device_Name`, `Attack`, `Attack_subType`, `label`. Поля event timestamp в CSV нет. Поэтому из набора нельзя достоверно восстановить фактическую частоту событий, 5-минутные пики, календарный рост и задержку доставки. В notebook эти расчёты приведены только как явно заданная модель replay-нагрузки; они не выдаются за измерения датасета или продакшена.

## Подготовка данных

1. Войдите в Kaggle и скачайте ZIP датасета из страницы выше.
2. Распакуйте ZIP в `data/raw/ids/` так, чтобы CSV лежал здесь:

   `data/raw/ids/BoTNeTIoT-L01-v2.csv`

   Допустимо оставить CSV в другом месте и передать его путь через `--source`.
3. Создайте Python 3.12 окружение, установите зависимости и выполните notebook:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lab1.lock.txt
.\.venv\Scripts\python.exe lab1/run_notebook.py
```

Для другого расположения CSV:

```powershell
.\.venv\Scripts\python.exe lab1/run_notebook.py --source 'D:\datasets\BoTNeTIoT-L01-v2.csv'
```

Чтобы форсировать повторный полный анализ и round-trip всех форматов:

```powershell
.\.venv\Scripts\python.exe lab1/run_notebook.py --force
```

Перед выполнением полного анализа проверьте свободное место на диске: источник занимает около 1,56 GiB, а временная полная сериализация Parquet/Avro требует дополнительного места. Runner размещает временные каталоги, kernel/Jupyter-файлы и кэши в игнорируемом `data/lab1/`, ограничивает CPU-библиотеки двумя потоками и запускает notebook тем Python, которым вызван runner.

Скачать ZIP можно через браузер, уже авторизованный в Kaggle, без API-токена. Альтернативный CLI-путь после загрузки ZIP: `.venv\Scripts\python.exe lab1/download_dataset.py --archive <путь-к-архиву>`.

Для macOS/Linux используйте `requirements-lab1.txt` и адаптируйте команды окружения. Локальное выполнение полного профиля зависит от свободных RAM/диска и скорости накопителя; runner не устанавливает системные пакеты и не меняет глобальные настройки машины.

## Фактические результаты выполненного запуска

Runner выполнен без `--force`: профиль с SHA-256 источника проверен и cache переиспользован, повторного полного анализа не было. Успешно исполнены 13 из 13 code cells; notebook содержит 4 inline PNG, ошибок выполнения нет. Профиль имеет статус `complete_with_quality_findings`: полный анализ завершён, ниже перечислены обнаруженные особенности качества.

- Источник: 7 062 606 строк × 27 полей, 1 678 174 220 байт (1.563 GiB); SHA-256 `e3cb8a91f0fb99afb81fefe55ee04743ed67dd7ec9ea4d119cf2a71c8a1a494d`.
- Форматы: исходный CSV 1 678 174 220 байт; Parquet 458 856 825 байт (на 72.7% меньше CSV); Avro 370 939 358 байт (на 77.9% меньше CSV). Оба round-trip прошли полное сравнение значений. Avro компактнее, но Parquet выбран для аналитики благодаря columnar layout; времена чтения в отчёте не сравниваются, поскольку scope замеров различается.
- Качество: пропусков нет; найдено 621 659 избыточных полных повторов. Они не удалялись: без event ID повтор может быть легитимным событием. За границы [-1, 1] выходят `HH_L0.1_pcc` (2 791 нарушения) и `HpHp_L0.1_pcc` (1 844); строки могут пересекаться, это не число уникальных записей. Несоответствий метки и категории атаки — 0. Great Expectations: 142/142 ожиданий прошли, отрицательный контроль отклонил испорченную метку.
- Ограничения: временных меток нет; частота, CV, пики, потери и задержки рассчитаны на синтетическом replay, а не измерены на устройствах. Категориальный текст занимает 15.76% байт CSV, но это не доля неструктурированных production logs.
- ROI остаётся финансовым сценарием, а не достигнутым результатом: base case даёт 93.73% годового ROI и 4.09 месяца окупаемости при текущих допущениях; low case убыточен. Цель MTTR −40% не измерялась.
